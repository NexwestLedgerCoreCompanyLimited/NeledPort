# M3 Mods Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** One-click server mod loaders (Oxide for Rust, BepInEx for Valheim), a plugin manager, and Workshop maps for Counter-Strike 2.

**Spec:** `docs/superpowers/specs/2026-10-29-neledport-design.md` (§5 mod loaders, M3).

## Global Constraints

- No new dependencies: zip extraction is a small Node reader (zlib inflate), with zip-slip protection.
- Loader downloads only over HTTPS from github.com or thunderstore.io (redirects to their CDNs allowed); the catalog rejects other hosts.
- Uninstall never leaves a broken server: files the loader added are removed, files it replaced are restored with SteamCMD validate.
- Loaders that patch game files (Oxide) are re-applied automatically after every server update.

## Review Focus

1. Zip entries with `../` or absolute paths → refused, nothing written outside the server folder.
2. Download host not on the allowlist (or redirect to one) → refused.
3. Update while a loader is installed → loader reinstalled, plugins kept.
4. Plugin file with the wrong extension → refused.
5. Loader download fails half-way → server files unchanged, error shown.

`modLoaders[]`: `id`, `name`, `download` (per platform URL), `stripTopFolder?`, `pluginDir`, `pluginExtensions`, `reapplyAfterUpdate?`, `env?` (per platform). `workshop`: `{ command }`. Rust → Oxide; Valheim → BepInEx; CS2 → `host_workshop_map {id}`.

### Task 3: `core/mods.ts` + manager
`installLoader`, `uninstallLoader`, `loaderStatus`, `listPlugins`, `setPluginEnabled`, `addPlugin`, `removePlugin`; launch env merges the installed loader's env; update re-applies loaders; `workshop(id, itemId)`.
