# M1 Core Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A user can add a Palworld or Valheim server, have NeledPort install SteamCMD and the server, start it, watch its live console, stop it gracefully, update it with an automatic backup, on Windows and Linux.

**Architecture:** All logic lives in `src/core/` (plain Node, no Electron imports, unit-tested). `ServerManager` orchestrates SteamCMD, processes, config and backups and emits events. Electron main exposes it over validated IPC; the renderer gets a server list, an add-server dialog, and Overview + Console tabs.

**Spec:** `docs/superpowers/specs/2026-10-29-neledport-design.md` (§4 lifecycle, §5 catalog, §7 security, milestone M1).

## Global Constraints

- No new runtime dependencies: Node built-ins only; archives use the system `tar` (Linux; Windows 10+ ships bsdtar which also reads `.zip`).
- Processes are spawned with argument arrays, never a shell.
- Every path from a definition is relative to the server's install dir; `{installDir}` is the only absolute value and comes from the app.
- Palworld REST and any RCON stay on 127.0.0.1; passwords are random by default and stored with Electron `safeStorage`.
- Update = backup → graceful stop → `app_update` → start (if it was running). Never skip the backup.
- SteamCMD URLs: `https://steamcdn-a.akamaihd.net/client/installer/steamcmd.zip` (Windows), `…/steamcmd_linux.tar.gz` (Linux).

## Review Focus

1. A server that never exits on graceful stop → killed after the timeout, state `stopped`, log says it was forced.
2. SteamCMD failure lines (`ERROR! Failed to install app`, no disk space) → install state `failed` with the line shown, not "success".
3. A crash while running → state `crashed`, last lines kept, no auto-restart loop.
4. Two servers with the same port → start refused before spawning.
5. `servers.json` corrupted or half-written → atomic writes; a bad file is renamed `.bad` and the app starts with an empty list and an error.

---

### Task 1: Placeholders and schema for settings, env and REST control
`core/template.ts`: `expand(value: string, ctx: { ports: Record<string, number>; settings: Record<string, string>; installDir: string }): string` replacing `{port:x}`, `{setting:x}`, `{installDir}`; unknown placeholder throws. Schema: platform `env`, top-level `settings[]` (`key`, `label`, `type` text|password|number, `default`, `minLength`, `secret`), `control.rest` (`port`, `basePath`, `username`). Catalog check: every placeholder in args/env refers to a declared port or setting. Add `games/valheim.json`; update `games/palworld.json`.
Tests: expansion, unknown placeholder, catalog rejects undeclared `{port:nope}`, real `games/` still valid.

### Task 2: SteamCMD
`core/steamcmd.ts`: `steamCmdDownload(platform)`, `steamCmdExecutable(dir, platform)`, `appUpdateArgs({ installDir, appId, validate })`, `parseSteamCmdLine(line): { kind: 'progress'; percent: number } | { kind: 'success' } | { kind: 'error'; message: string } | null`, `ensureSteamCmd(dir, deps)` (download with fetch, extract with tar, skip if present), `runSteamCmd(exe, args, onLine): Promise<{ ok: boolean; error?: string }>`.
Tests: args order (`+force_install_dir` before `+login anonymous`), progress/success/error parsing on real output samples.

### Task 3: Server process
`core/process.ts`: `class ServerProcess extends EventEmitter` — `start(launch)`, `stop({ graceful: () => Promise<void>, timeoutMs })`, `state`, `lines()` (ring buffer 2000), events `state`, `line`, `exit`. Log appended to a file. Crash = non-zero/unexpected exit while running.
Tests with a fake Node server script: lines arrive, graceful stop, forced kill after timeout, crash detection.

### Task 4: Palworld adapter
`core/palworld.ts`: `readOptionSettings(ini)`, `writeOptionSettings(ini, patch)` for the `OptionSettings=(…)` tuple (quoted strings with commas, nested lists), `prepareConfig(installDir, platform, values)` (copy `DefaultPalWorldSettings.ini` when missing), `restClient({ port, username, password })` with `save()`, `shutdown(waitSeconds, message)`, `info()`; 5 s timeouts.
Tests: parse/patch round-trip on a realistic line; REST client against a local `http` server.

### Task 5: Backups and store
`core/backup.ts`: `createBackup(saveDir, backupsDir, reason)`, `listBackups`, `pruneBackups(keep)`, `restoreBackup`. `core/store.ts`: `loadServers(file)`, `saveServers(file, list)` (atomic temp+rename), validation. `core/ports.ts`: `isPortFree(port, protocol)`.
Tests: backup round-trip, prune keeps newest, corrupt store → `.bad` + empty, port in use detected.

### Task 6: ServerManager
`core/manager.ts`: `create(input)`, `install(id)`, `start(id)`, `stop(id)`, `update(id)`, `backup(id)`, `list()`, events `changed(server)`, `line(id, text)`, `progress(id, percent)`. Graceful stop by `control.type`: `rest` → REST save+shutdown, `signal` → SIGINT on POSIX (Windows: backup then kill, flagged in the UI), `stdin` → write command.
Tests with fake steamcmd runner and fake processes: update order (backup before stop), port conflict refusal, state transitions.

### Task 7: Electron wiring and UI
Main: one `ServerManager`, IPC `servers:*` with payload guards, events forwarded to the window, secrets via `safeStorage`, quit asks to stop running servers. Renderer: sidebar list with status, Add server dialog (game → name/settings/ports), Server view with Overview (status, Start/Stop/Restart/Update/Backup, install progress, ports to open) and Console (live log, search).
Verify: typecheck, tests, build, launch and screenshot.

### Task 8: Real-server CI test
`scripts/e2e-valheim.mjs` drives `ServerManager` headless on Linux: install SteamCMD + Valheim, start, wait for the ready log line, stop with SIGINT, assert the world was saved. Workflow `e2e.yml` on `workflow_dispatch` (ubuntu-latest).
